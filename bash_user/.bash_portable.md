# bash_user

Non-root user bash customization. Requires `fzf`.

## Requirements

```bash
sudo apt install fzf              # required
sudo apt install bat              # optional - used by `list` for syntax highlighting
sudo apt install bash-completion  # optional - enables tab-completion for commands
```

## Files

| File                | Description                                     |
|---------------------|-------------------------------------------------|
| `.bashrc_`          | customization block - append to `.bashrc`       |
| `.bash_prompt`      | prompt with git segment and hostname alias      |
| `.bash_aliases`     | aliases and small functions                     |
| `.bash_functions`   | fzf-powered functions                           |
| `.inputrc`          | key bindings                                    |
| `.dircolors`        | `ls` colors (ANSI 16, follows terminal palette) |
| `.bash_portable.md` | this file (offline reference)                   |
| `dedup_history.sh`  | one-shot history deduplication script           |
| `deploy.sh`         | deploy script                                   |

## Deploy

```
./deploy.sh [-u target_user] [-f extra_file] host1 [host2 ...]
```

- Host `.` - local deploy, other arguments are SSH hosts
- Default target user: `$USER` (`-u jenkins` deploys to `/home/jenkins`, needs sudo)
- Default files: `.bash_prompt .bash_aliases .bash_functions .inputrc .dircolors .bash_portable.md`
- `-f` adds files beyond the default set (repeatable)

### Initial deploy

Once per host / account:

1. Copy the files. Add `.bashrc_` and `dedup_history.sh` with `-f`, because they are not in the default set:

   ```bash
   ./deploy.sh -f .bashrc_ -f dedup_history.sh . host1 host2
   ```

2. On each host, install the dependencies:

   ```bash
   sudo apt install fzf bat bash-completion   # bat and bash-completion are optional
   ```

3. Append `.bashrc_` to `.bashrc`, then remove it:

   ```bash
   cat ~/.bashrc_ >> ~/.bashrc && rm ~/.bashrc_
   ```

   `.bash_aliases` is loaded automatically by the stock `.bashrc` if it exists.

4. Deduplicate existing history (see [History deduplication](#history-deduplication)).
   The script removes itself when it succeeds:

   ```bash
   ~/dedup_history.sh
   ```

5. Restart bash: `exec bash`, or open a new terminal / ssh session.

### Update (after changes in the repo)

1. Copy the default files again:

   ```bash
   ./deploy.sh . host1 host2
   ```

2. Only if `.bashrc_` changed: edit `~/.bashrc` by hand and update the block between
   `==[ Customization begin ]==` and `==[ Customization end ]==` (compare with `.bashrc_` in the repo):

   ```bash
   nano ~/.bashrc
   ```

3. Restart bash: `exec bash` (needed for `.inputrc` and `.bashrc` changes).

## Hostname aliases

Priority: `~/.hostname.alias` → `HOSTNAME_ALIASES` array in `.bash_prompt` → `/etc/hosts` → short hostname.

To set an alias for the current machine, create `~/.hostname.alias` with a single line:

```bash
echo "dev" > ~/.hostname.alias
```

To update the built-in defaults for well-known servers, edit `HOSTNAME_ALIASES` in `.bash_prompt`.

### `ffind` options

```
ffind [-sIibH] [-t "pattern"] [dir] "filename_pattern"
```

| Option         | Description                               |
|----------------|-------------------------------------------|
| `-s`           | recursive                                 |
| `-t "pattern"` | search file contents (regex)              |
| `-i`           | case-insensitive content search           |
| `-b`           | bare output (paths only, no file content) |
| `-H`           | include hidden files/dirs                 |
| `-I`           | case-insensitive filename match           |

Always quote glob patterns - `ffind "*.java"` not `ffind *.java`.

## Clipboard (`clip`)

Copies to the clipboard of the machine where the terminal runs - also from an ssh session.
One-way only (copy, no paste); meant for small outputs.

```bash
dir | clip          # command output
clip "$PWD"         # text from arguments
dir > >(clip)       # closest to TCC's "dir > clip:"
```

Uses the OSC 52 escape sequence: the terminal (Kitty, Windows Terminal) puts the data into its clipboard.
Trailing newlines are removed, so a pasted path does not run as a command.
Inside tmux: `set -g set-clipboard on`.

## fzf keys

`.bashrc_` sets `FZF_DEFAULT_OPTS` (only if not already set): `--color=16 --bind=home:first,end:last`.

| Key             | Action in fzf pickers (`cd`, `dh`, `list`, `rm`, `use`, PgDn history) |
|-----------------|-----------------------------------------------------------------------|
| Home / End      | first / last entry                                                    |
| PgUp / PgDn     | page up / down (fzf default)                                          |
| Up / Down       | previous / next entry                                                 |
| Ctrl+A / E      | start / end of the query line                                         |
| Tab / Shift+Tab | toggle mark, move down / up (`use`, Ctrl+T)                           |

Requires fzf 0.24+ (`first`/`last` actions); Ctrl+T with hidden files needs 0.48+ (`--walker`).

Ctrl+T / Alt+C / Ctrl+R come from fzf's own `key-bindings.bash`, which `.bashrc_` sources from the
Ubuntu package path `/usr/share/doc/fzf/examples/`. For fzf installed by hand, change that line in `~/.bashrc`
to its `key-bindings.bash` (or `eval "$(fzf --bash)"`, which also adds `**<Tab>` completion).

## Project directory (`~~`)

`~~` jumps to `$PROJECT_DIR` - alone (alias), or as `cd ~~` / `cd ~~/src` (only with `cd`, not in other commands). `.bashrc_` sets it to `$HOME`;
change the line in `~/.bashrc` to the project you currently work on:

```bash
PROJECT_DIR="$HOME/repos/my-project"    # target of ~~ - set to the project you work on
```

## `use` (TCC `SELECT`)

Pick items with fzf (Tab marks several), then do something with them:

| Form                 | Action                                                         |
|----------------------|----------------------------------------------------------------|
| `use`                | selection to the clipboard (`clip`), shell-quoted              |
| `use cmd .. {} ..`   | `cmd` once per item, `{}` = the name (also inside a word)      |
| `use cmd ..`         | `cmd` once, all items appended at the end                      |

The list is `ls -A` of the current directory (dirs first, colored), or stdin when piped.
Each command is printed before it runs. Names starting with `-` get `./`.

```bash
use                                  # pick -> clipboard
use cp {} /tmp                       # copy each picked item
use mv {} {}.bak                     # rename each
use tar czf x.tgz                    # one archive with all picked items
find . -name '*.log' | use rm {}     # pick from a find result (instead of TCC's (*.log))
```

`cmd` can be a function (`use rm {}` goes to the trash with `RM_TRASH=1`, `use list {}`), not an alias.

## Trash (`rm`)

`RM_TRASH=1` in `~/.bashrc` (`.bashrc_` sets 0): `rm` moves files and directories to the trash
with `gio trash` - the same trash as Dolphin (`~/.local/share/Trash`). Like `del` in Take Command;
the forced delete is `del` (`rm -rf`) or `command rm`.

- without `gio` installed `rm` stays the plain `rm` - the same `.bashrc` works on every host
- rm options (`-r`, `-f`, `-i` ...) are ignored: `rm -rf dir` goes to the trash too
- scripts and `sudo rm` are not affected (the function exists only in the interactive shell)
- no trash on that filesystem (other mount, no write access) -> `gio` error, use `del`

Browse / restore: Dolphin -> Trash (`trash:/`). Empty: `ktrash6 --empty`.
`gio trash --list` / `--restore` need the `gvfs` package (not installed on Kubuntu).

## `.direnv`

After every directory change (`cd`, `autocd`, `dh`, `~~`, Ctrl+Page Down ...) the file `./.direnv`
is sourced into the current shell - e.g. to set `JAVA_HOME` or activate a venv for a project.
It is sourced only if it is a regular file, owned by you and **executable**:

```bash
chmod +x .direnv
```

Note: git keeps the executable bit, so a cloned repo can bring an executable `.direnv`.
Check `.direnv` files in repos you clone. A `.direnv/` directory (used by the `direnv` tool) is ignored.

## History deduplication

`HISTCONTROL=erasedups` is set in `.bashrc_` - a repeated command removes its older copies
from the in-memory history. By default bash only *appends* new commands to `~/.bash_history` on exit,
so the file would keep the old copies. `.bashrc_` therefore sets an EXIT trap:

```bash
[[ -z $BASH_EXECUTION_STRING ]] && trap 'history -w; unset HISTFILE' EXIT
```

On exit the file is rewritten from the in-memory history (already deduplicated); `unset HISTFILE`
stops bash from appending the session again afterwards. Consequences:

- with several terminals open, the last one to exit wins - commands from the others can be lost
- a closed window or a dropped ssh connection (SIGHUP) runs the trap too; only SIGKILL saves nothing
- `exec bash` does not run the trap; it appends the session (a few duplicates, removed when the command is used again)
- `bash -i -c ...` (IDEs and tools reading the shell environment) does not load history, so the trap is not set there - otherwise it would empty the file

For history accumulated before this setting, run `dedup_history.sh` once - step 4 of [Initial deploy](#initial-deploy).

Editing `~/.bash_history` by hand: the EXIT trap would overwrite the file from memory and discard the edits.
After editing, reload the history in the same session (other open terminals still overwrite on exit):

```bash
vi ~/.bash_history
history -c; history -r    # clear in-memory history, read it from the file
```

## `ls` colors

ANSI 16 color scheme via `~/.dircolors` - follows the terminal palette (Selenized Light in Kitty / Windows Terminal).

Colors are for **grouping** only: one hue per file group, no bold-only differences.
Hues roughly follow the IntelliJ Selenized Light theme.

| Group                                                                    | ANSI       | IntelliJ analogy        |
|--------------------------------------------------------------------------|------------|-------------------------|
| directories                                                              | blue       | keywords, folder icons  |
| executables                                                              | green      | Run action              |
| symlinks                                                                 | cyan       | strings                 |
| source code (`.java .kt .js .ts .py .c .sh .sql` ...)                    | magenta    | function declarations   |
| config / data / docs (`.xml .json .yaml .conf .properties .md .txt` ...) | yellow     | metadata, annotations   |
| archives, images, audio, video (`.tar .zip .jar .png .mp4` ...)          | red        | -                       |
| compiled, logs, backups (`.class .o .so .pyc .log .bak .tmp` ...)        | gray       | comments, ignored files |
| broken symlinks                                                          | red bar    | -                       |
| setuid / setgid                                                          | yellow bar | -                       |

## Kitty

The repo does not set terminal colors. The palette comes from Kitty's `selenized-light.conf`
(font: CommitMonoV143). Prompt and `ls` colors use ANSI 16, so they follow the Kitty theme.
`list` (batcat `--theme=ansi`) and fzf (`--color=16` in `FZF_DEFAULT_OPTS`) do too.
